## 🏗️ Текущая архитектура системы

Система построена на принципах атомарного линейного конвейера (Pipeline) обработки исходного кода, полностью изолированного внутри Docker-контейнера.

```text
[CLI Аргументы флага] -> [ProjectIndexer] -> [CakeAnalyzer] -> [JsonSchemaValidator] -> [PromptGenerator] -> [.prompt_output/]

```

1. **Входная точка (`app.php`):** CLI-интерфейс, гибко валидирующий позиционные аргументы и изолирующий опциональный флаг `--instruction="..."` для передачи кастомного ТЗ.
2. **Глобальный индексатор (`ProjectIndexer`):** Сканирует дерево каталогов CakePHP приложения, строго фильтрует `.php` файлы, строит инвертированный граф связей проекта и вычисляет метрику `Influence Score`.
3. **Детальный парсер (`CakeAnalyzer`):** Управляет контекстом статического анализа. В зависимости от целевого слоя распределяет задачи:
* На базе `CakeV2PropertyExtractor` собирает runtime-модели из `$uses`/`loadModel` и компоненты контроллеров.
* На базе `CakeV2ModelExtractor` осуществляет глубокий разбор ORM-ассоциаций (`belongsTo`, `hasMany` и т.д.).


4. **Слой валидации (`JsonSchemaValidator`):** Страж контракта данных. Проверяет сгенерированный массив метаконтекста на строгое соответствие `analysis-schema.json`. Поддерживает полиморфизм пустых легаси-массивов (`oneOf`).
5. **Генератор промптов (`PromptGenerator`):** Атомарно склеивает внешний изолированный текстовый макет (`base_layout.txt`), JSON-контекст анализа, кастомные инструкции пользователя и автоматически подгружаемый исходный код целевого файла за один проход, полностью исключая циклическую рекурсию подстрок.
6. **Выделенное хранилище (`.prompt_output/`):** Изолированная директория в корне генератора, зеркалирующая структуру путей исходного проекта, куда тихо складываются финальные файлы `*.prompt.txt`. Исключена из Git через `.gitignore`.

## 📊 Контракт данных (Валидный JSON-артефакт)

Ниже представлена утвержденная структура метаданных, успешно проходящая валидацию схемы:

* **`system_meta`**: Конфигурация легаси-окружения (Framework, версии системы и PHP).
* **`task_context`**: Сведения о целевом слое приложения (`target_layer`) и физическом расположении файла.
* **`metrics`**: Оценка связности кода (`connectivity`) и уровня влияния (`influence_score`).
* **`relations`**: Список зависимостей:
* `models` — собираются динамически через парсинг `$this->loadModel()`.
* `components` — используемые в контроллере компоненты.
* `associations` — реляционные связи данных (`belongsTo`, `hasMany`, `hasOne`, `hasAndBelongsToMany`), автоматически извлекаемые из слоя *Model*.


* **`impacted_by`**: Сводный список компонентов, на которые данный файл оказывает прямое влияние.
