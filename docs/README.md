# CakePrompt Engineering System

**CakePrompt Engineering System** — это специализированный инструмент автоматизации промпт-инжиниринга, спроектированный для генерации высококачественных, контекстно-зависимых инструкций (промптов) для Large Language Models (LLM). 

Система осуществляет глубокий статический анализ legacy-кода на базе фреймворков **CakePHP (v2 / v3 / v4)** и компилирует изолированные промпты с жестким контролем синтаксиса **PHP 5.6** для решения задач разработки, рефакторинга и отладки.

---

## 🔄 Workflow системы

Процесс работы с системой состоит из трех ключевых этапов:
1. **Анализ кода:** Автоматический сбор метаданных, связей и метрик безопасности (`Influence Score`).
2. **Генерация промпта:** Сборка адаптивного технического задания для нейросети с автоматической инжекцией исходного кода целевого файла за один проход.
3. **Отправка в LLM:** Передача изолированного промпта в модель (в ручном режиме) для получения эталонного кода.

```text
[Исходный код CakePHP] ──> (Анализ кода) ──> [JSON Контракт] ──> (Генерация промпта) ──> [.prompt_output/*.txt] ──> 🤖 LLM

```

---

## 🛠 Схема пайплайна системы

### 1. Анализатор кода (`Analyzer`)

* **Мультиверсионная поддержка:** Анализирует код на основе конвенций фреймворков CakePHP v2, v3 и v4 с учетом ограничений языка PHP 5.6.
* **Извлечение связей и зависимостей:** В процессе AST-обхода определяет архитектурные зависимости между файлами:
* `Controller` -> `Model` (включая динамические вызовы `loadModel`)
* `Model` -> `Model`


* **Расчет метрик влияния:** Вычисляет уровень влияния измененного файла на остальную систему (**Influence Score**) и общую связность компонента (**Connectivity**) на основе инвертированного графа проекта.
* **Строгий контракт данных:** Возвращает структурированный анализ в формате JSON и валидирует его с помощью `justinrainbow/json-schema`. Любое отклонение структуры данных от эталонной схемы прерывает пайплайн.

### 2. Генератор промптов (`Generator`)

* **Адаптивные стратегии:** Формирует промпт на основе переданного типа задачи:
* `FEATURE`: Директивы для создания фич по парадигме *Fat Model / Skinny Controller* через ORM, без сырого SQL.
* `REFACTOR`: Фокус на сохранении обратной совместимости интерфейсов при высоком уровне влияния (Influence Score). Консервативные изменения.
* `DEBUG`: Инструкции по ручной защите от Null-pointer исключений (отсутствие `?->` в PHP 5.6) и legacy-логированию через `CakeLog`.


* **Внешнее макетирование:** Текст промпта полностью изолирован во внешних текстовых файлах-макетах. Сборка контекста выполняется атомарным проходом массива замен через `str_replace`, что исключает циклическую или рекурсивную подмену подстрок.
* **Изолированный вывод артефактов:** Финальный промпт автоматически сохраняется в выделенную директорию `.prompt_output/`, зеркалирующую структуру каталогов исходного проекта, предотвращая загрязнение кодовой базы legacy-приложения.

## � Использование системы

**Базовый синтаксис:**
```bash
docker-compose run --rm analyzer php app.php <путь_к_файлу> <тип_задачи> [--instruction="текст"]
```

**Типы задач:**
- `REFACTOR` - рефакторинг с сохранением обратной совместимости
- `FEATURE` - создание новой функциональности
- `DEBUG` - отладка и исправление ошибок

**Примеры:**
```bash
# Рефакторинг контроллера
docker-compose run --rm analyzer php app.php /sic/app/Controller/SicsController.php REFACTOR

# Новая фича в модели с кастомной инструкцией
docker-compose run --rm analyzer php -d memory_limit=-1 app.php /sic/app/Model/Sic.php FEATURE --instruction="Добавить валидацию для поля amount"

# Отладка
docker-compose run --rm analyzer php app.php docs/UsersController.php DEBUG

# Изменение View шаблона (.ctp файл)
docker-compose run --rm analyzer php app.php /sic/app/View/Centers/admin_index.ctp FEATURE
```

**Результат:**
- Промпт сохраняется в `.prompt_output/<путь_к_файлу>/<тип>.prompt.txt`
- Содержит: контекст анализа, связи БД, правила валидации, исходный код
- Готов к отправке в LLM для получения кода

**Для больших файлов:**
```bash
docker-compose run --rm analyzer php -d memory_limit=-1 app.php /sic/app/Model/Sic.php REFACTOR
```

**Кастомные инструкции:**
```bash
# Добавление пользовательских требований через флаг --instruction
docker-compose run --rm analyzer php app.php /sic/app/View/Centers/admin_index.ctp FEATURE --instruction="Добавить фильтр по дате"

# Рефакторинг с конкретным требованием
docker-compose run --rm analyzer php -d memory_limit=-1 app.php /sic/app/Model/Sic.php REFACTOR --instruction="Оптимизировать метод authorizationLevelsUpdate"

# Отладка с описанием проблемы
docker-compose run --rm analyzer php app.php docs/UsersController.php DEBUG --instruction="Исправить ошибку валидации при создании пользователя"
```

Кастомная инструкция автоматически добавляется в промпт и интегрируется с базовыми директивами задачи.

## � Архитектура и структура файлов

```text
cake-prompt-system/
├── docker-compose.yml       # Контейнеризация приложения (PHP 8.3 CLI)
├── Dockerfile               # CLI образ с предустановленным Composer
├── composer.json            # Зависимости: nikic/php-parser, justinrainbow/json-schema
├── app.php                  # Главная точка входа (CLI-оркестратор, автодетекция корня)
├── .gitignore               # Исключает локальную папку .prompt_output из репозитория
├── .prompt_output/          # Изолированное хранилище сгенерированных промптов (автосоздание)
└── src/
    ├── Analyzer/
    │   ├── CakeAnalyzer.php               # Главный класс анализа, детекция слоев, версий и сборка контекста
    │   ├── CakeV2PropertyExtractor.php    # AST-обходчик для контроллеров (извлекает $uses, loadModel, компоненты)
    │   ├── CakeV2ModelExtractor.php       # AST-обходчик для моделей (извлекает ассоциации и $validate)
    │   └── ProjectIndexer.php             # Глобальный сканер проекта (индексация входящих связей)
    ├── Generator/
    │   ├── PromptGenerator.php            # Фабрика генерации промптов (оркестратор стратегий)
    │   ├── AbstractPromptTemplate.php     # Базовый компилятор (чтение макетов, инжекция кода, замена подстрок)
    │   └── Templates/
    │       ├── base_layout.txt            # Единый текстовый шаблон промпта со строгими правилами PHP 5.6
    │       ├── RefactorTemplate.php       # Стратегия для задач типа REFACTOR (защита интерфейсов)
    │       ├── FeatureTemplate.php        # Стратегия для задач типа FEATURE (Парадигма Fat Model)
    │       ├── DebugTemplate.php          # Стратегия для задач типа DEBUG (Null-safety в PHP 5.6, логи)
    │       └── ViewTemplate.php          # Стратегия для View слоя (.ctp файлы, хелперы CakePHP)
    └── Shared/
        ├── JsonSchemaValidator.php        # Валидатор данных на базе justinrainbow/json-schema
        └── analysis-schema.json           # Жесткая JSON-схема контракта между Analyzer и Generator

```

## 🎯 Что уже реализовано (Done)

1. **Docker-окружение:** Стабильная CLI-сборка на базе `php:8.3-cli-alpine` с Composer.
2. **Глобальный индексатор проекта (`ProjectIndexer`):** Автоматически определяет корень приложения, сканирует проект (только `.php` файлы) и собирает инвертированный граф для расчета метрик влияния.
3. **AST-анализ CakePHP v2 Контроллеров:** Стабильный разбор свойств, динамических `loadModel` и компонентов.
4. **Глубокий анализ Моделей CakePHP v2:** Модуль `CakeV2ModelExtractor` извлекает ORM-ассоциации (`belongsTo`, `hasMany`, `hasOne`, `hasAndBelongsToMany`) и правила валидации (`$validate`) с поддержкой альтернативных форматов.
5. **Поддержка View слоя:** Детекция `.ctp` файлов и генерация промптов с инструкциями по использованию хелперов CakePHP (`$this->Html`, `$this->Form`, `$this->Paginator`).
6. **Валидация контракта (JSON Schema):** Пакет `justinrainbow/json-schema` гарантирует 100% корректность структуры данных.
7. **Кастомные инструкции:** Поддержка флага `--instruction="..."` для передачи пользовательских требований в промпт.
8. **Безопасный движок генерации:** Шаблоны вынесены во внешние `.txt` файлы. Атомарная замена маркеров через `str_replace`.
9. **Автоматическая инжекция исходного кода:** Модуль генератора самостоятельно считывает и изолирует код целевого файла.
10. **Изолированное хранилище (`.prompt_output/`):** Промпты сохраняются в отдельной директории, исключенной из Git.
